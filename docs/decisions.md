# 設計判断ログ

作成時に行った判断（特にマニュアルに記載が見つからなかった箇所の扱い）を記録します。
「出典」は z/OS 3.2 のマニュアル（ページは PDF のページ番号）。

## 全体方針

| # | 判断 | 理由 |
|---|---|---|
| D01 | JCL 練習用シミュレータ（jcl-terminal）とは別のリポジトリにする | 対象（JCL とオペレーター操作）が異なるため |
| D02 | ブラウザで開くだけで動く単一ページ（`index.html`）＋ロジック（`engine.js`）。サーバー・ビルド不要 | 手元でダブルクリックで使える形が一番手軽。Node.js があるのでテストは `node` で同じ engine.js を直接動かす |
| D03 | 対象は z/OS 3.2 + JES2 の単一システム（SYSA）。sysplex（PLEX1、相手 SYSB）は XCF 関連の操作だけ模擬 | マニュアル一式が z/OS 3.2・JES2 なので。JES3 は対象外 |
| D04 | 画面と解説は日本語、コンソールのメッセージ本文は英語（実機どおり） | 実機の操作感を優先。各メッセージをクリックするとマニュアルの出典付き日本語解説を表示 |
| D05 | 時間経過はボタン（「時間を1分進める」）とコマンド `WAIT n`（シミュレータ独自）で進める | テストを決定的（毎回同じ結果）にするため。実時間で勝手に進むと再現テストができない |
| D06 | 障害は「シナリオ」チェックボックスで注入する方式 | 1つの画面で正常系と各種エラーを体験・テストできるように |

## メッセージ・挙動の判断（マニュアルに明記がない／簡略化した箇所）

| # | 判断 | 根拠・理由 |
|---|---|---|
| D10 | LOAD パラメーター 7桁目（IMSI）が表にない文字のときは既定値（.）扱いにし、シミュレータ注記を出す | System Commands p.32-33 の表に定義のない文字の挙動は記載が見つからなかった |
| D11 | LOAD パラメーター 8桁目（代替核）が 1 / . / 空白 以外のときは待機状態 088 理由 0E | 本シミュレータの SYS1.NUCLEUS には IEANUC01 系しか置かない設定。088-0E「核拡張 IEANUC1x/2x が見つからない」が最も近い（System Codes 088） |
| D12 | LOAD パラメーターの IODF 装置に LOADxx が無い（装置が存在しない場合も含む）ときは 088 理由 00 | 088-00「IODF ボリューム／SYSRES 上に LOADxx が見つからない」。存在しない装置の個別挙動は簡略化 |
| D13 | ロードアドレスが存在しない装置のときは HMC 側エラー（MVS メッセージなし） | ハードウェア（HMC）の挙動。MVS マニュアルの範囲外なので「シミュレータ注記」として表示 |
| D14 | NIP 中の応答は `R 00,xxx` のほか、空 Enter（＝応答なし Enter）も受け付ける | IEA347A/IEA101A/IEA336A の説明に「press ENTER」とあるため |
| D15 | IEA888A（時刻確認）への不正応答は同じプロンプトを再表示 | 不正応答時の専用メッセージは見つからなかった |
| D16 | $HASP454 に N と答えた場合は、実機の HASP416/HASP417 の確認対話を省略し、$HASP428 で JES2 終了 | 実機では N → HASP416/460 → HASP417 の対話（JES2 Messages $HASP454）。対話の再現は範囲外として簡略化 |
| D17 | JES2 未起動時の `$` コマンドは IEE305I（COMMAND INVALID） | JES2 が無いとどのサブシステムも $ コマンドを処理しないため、MVS 側で不正コマンド扱いになる想定 |
| D18 | JES2 未起動時に JES2 配下の STC（VTAM/TCPIP/TSO）を START するとシミュレータ注記で拒否 | 実機では START が JES2 待ちになる等の挙動があるが、マニュアルからは確定できなかった |
| D19 | `$P JES2` を作業中に出すと $HASP607＋$HASP608 を表示し、JES2 は停止しない。作業が終わったら再度 `$P JES2` が必要 | JES2 Commands p.38「作業中なら $P として処理され drain する」。drain 後の自動終了有無は簡略化して再投入方式に |
| D20 | `V XCF,SYSA,OFFLINE` → IXC371D に SYSNAME=SYSA で応答すると、SYSA は待機状態 0A2 理由 004 | System Codes 0A2-004「オペレーターが VARY XCF,sysname,OFFLINE を入力」。相手システム側の IXC102A は注記として表示のみ |
| D21 | IXC405D に R と応答した場合は IXC207A（COUPLExx 指定）を出し、応答後に XCF 初期化をやり直す | IXC405D の R の説明。COUPLExx の中身は模擬しない |
| D22 | JES2 停止前に `Z EOD` を出しても実行はできる（IEE334I）が、採点で「順序誤り」とする | JES2 Commands p.39「$P JES2 完了後に HALT EOD」 |
| D23 | 不明な JES2 コマンドは `$HASP003 RC=(01)` 形式の簡易表示 | $HASP003 は $SCAN エラー全般のメッセージ。理由コードの細かい再現は範囲外 |

| D25 | IEE114I（D A,L の応答）だけは z/OS 3.2 のメッセージ集で定義箇所を見つけられず、Redbook（SG24-6988、z/OS 1.13）の出力例を出典にした | コーパス検索で Vol 7 にヒットなし。解説パネルにもその旨を明記 |

| D29 | IMSI が C / P / S / . のときは NIP 中の情報メッセージ（IEA370I など）を表示しない | System Commands p.32-33 の IMSI 表どおり。テスト E24 で確認 |

## エラー洗い出しの方法

1. `tools/extract_errors.py` で、マニュアル本文（PDF をテキスト化したもの）から次を機械抽出 → 387 件（[error-candidates.md](error-candidates.md)）
   - System Messages Vol 6 の IEA メッセージのうち、出所（Source）や説明に IPL/NIP/system initialization を含み、応答要求（A/D）・待機（W）、または再指定・再IPLを求めるもの
   - Vol 10 の IXC 応答要求のうち初期化・VARY XCF・sysplex に関するもの
   - JES2 Messages のうち初期化／終了モジュール（HASPIR*、HASPTERM、HASPWARM）が出す応答要求・終了メッセージ、$P JES2 関連
   - Vol 7 / Vol 8 の操作コマンド（REPLY/START/STOP/CANCEL/FORCE/HALT）が拒否されるメッセージ
   - System Codes の待機状態コードのうち IPL/NIP/LOADxx/IODF/SYSRES/マスターカタログに関するもの
2. その中から、オペレーターの操作で起こり、操作で回復できるものを選んでシミュレータに実装し、1件ずつテストケース化（[error-catalog.md](error-catalog.md)、86 件）
3. テストランナーは「エンジンが出しうる全メッセージ ID・待機状態コードがテストで1回以上出たか」「すべてに解説と出典があるか」も検査
