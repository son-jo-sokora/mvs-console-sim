## jcl-terminal との連携モード

| # | 判断 | 理由 |
|---|---|---|
| D37 | 2つを1つのアプリに統合せず、別々のまま同じサイトの2つのタブを BroadcastChannel でつなぐ | jcl-terminal は約3,800行の1ファイルで、画面・JCL 処理・保存が一体。統合すると作り直しと既存テスト約140件の移行が必要。連携なら両方とも単独でもこれまでどおり動く |
| D38 | ジョブを「いつ動かすか」はシミュレータ（SYSA の JES2）、「中身と結果」は jcl-terminal が持つ | JES2 の役割（キュー・イニシエーター・保留・$S/$P）とプログラムの実行を自然に分けられる。両側で同じことを決めると食い違う |
| D39 | 連携中、jcl-terminal は SYSA の TSO 利用者 USER01 として振る舞う。TSO が動いていないと SUB できない。P TSO の IKT010D の対象にもなる | 実機でも TSO が止まっていれば利用者は投入できない。オペレーターの操作が利用者に影響することを体験できるように |
| D40 | 連携中は jcl-terminal の SDSF の / コマンドとオペレーター演習（OP01〜）を止め、自分のジョブへの $HJ/$AJ/$CJ と SDSF 行コマンド H/A/C だけをシミュレータに送る | オペレーターの操作を2か所でできると、どちらの状態が正しいか分からなくなる |
| D41 | データセットの奪い合いは、ジョブの DD の DSN と DISP から判定する（SHR 同士だけ共用可）。待つジョブには IEF861I・IEF863I・IEF099I を出し、使えるようになったら自動で進める | Vol 8 IEF099I「データセットが使えるようになると予約して続行」。IEF863I の RC/RSN 値（RC=00000004 RSN=00000000）は ENQ の戻りコードの細部まで確認していない簡略表示 |
| D42 | 連携ジョブの実行時間は既定 0 分（すぐ終わる）。演習やテストで必要なときだけ、シミュレータ側でジョブ名ごとに分数を決める（linkDurations） | jcl-terminal の JCL に実行時間の書き方はない。架空の JCL パラメーターを作らずに、待ちの場面を作るため |
| D43 | システムが落ちたときに実行中だった連携ジョブは、次の JES2 ウォームスタートで $HASP406 を出して再実行待ちに戻す。コールドスタートでは連携ジョブと出力をすべて消す | JES2 Messages $HASP406「ウォームスタート時に実行中だったジョブを再実行待ちに戻す」。コールドスタートはスプールを初期化する |
| D44 | 連携の自動テストは2段にする: Node と tests/run.html では jcl-terminal と同じ受け答えをする模擬端末（link-mock.js）を相手にし、tests/link-e2e.html では本物の jcl-terminal を相手に同じケースと連携演習の模範解答を流す | 模擬端末だけだと本物とずれても気づけない。本物だけだとテストが遅く Node で回せない。両方で同じケースが通ることで、模擬端末の正しさも確かめる |
| D45 | 演習ページの連携演習の模範解答の画面は、模擬端末を相手に作る（ページに注記） | ページを開いただけでは jcl-terminal が無いため。本物との一致は D44 の結合テストで確認 |

## SYSLOG 調査演習

| # | 判断 | 理由 |
|---|---|---|
| D46 | SYSLOG には、IMSI でコンソールに出なかった初期化中のメッセージも含めてすべて残す（シミュレータの注記・HMC の表示・「（連絡）」は残さない） | System Commands p.4「メッセージを抑止したときは、初期化の後にハードコピーログを確認すること」。実機の SYSLOG・ハードコピーログの開始時期の細かい違いは簡略化 |
| D47 | SYSLOG のレコードの並びは jcl-terminal の SYSLOG 画面と同じ（種別・システム名・年日・時刻・ジョブ番号またはコンソール名・本文）。コマンドは種別 NC、コンソール名 MSTCON | 2つのアプリで見え方をそろえる。実機のレコード形式の全項目（ルーティングコードなど）は再現しない |
| D48 | 「前のシフトの出来事」は文章で書かず、シミュレータで実際に操作（IPL・ジョブ投入・コマンド・リセット）して作る。その間のコンソール表示は隠し、SYSLOG にだけ残す | ログと動作が食い違わないようにするため（手順例と同じ考え方） |
| D49 | 診断は「原因の選択肢＋根拠のメッセージ ID」で報告させる。根拠は ID が含まれていれば正解とし、時刻までは問わない | 自由記述の採点は難しい。選択肢だけだと当て推量でも正解できるので、根拠の ID を合わせて求める |
| D50 | 演習の「操作の採点」（停止手順など共通の項目）は、挑戦を始めてからの操作だけを対象にする | 夜勤者のリセットなど、前のシフトの操作で減点されないように |
| D51 | XS5 の異常終了ジョブ（PAYCALC）のメッセージは、jcl-terminal の ABEND サンプル（S806）が出す文面と同じにした（CSV003I・CSV028I・IEA995I・IEF450I） | jcl-terminal 側で確認済みの文面を使い、2つのアプリで同じ現象が同じに見えるように。XS5 は前のシフトの出来事なので、jcl-terminal との連携ではなくシミュレータ内のジョブとして作った（連携先のタブは挑戦の開始前には存在しないため） |

## エラー洗い出しの方法

1. `tools/extract_errors.py` で、マニュアル本文（PDF をテキスト化したもの）から次を機械抽出 → 387 件（[error-candidates.md](error-candidates.md)）
   - System Messages Vol 6 の IEA メッセージのうち、出所（Source）や説明に IPL/NIP/system initialization を含み、応答要求（A/D）・待機（W）、または再指定・再IPLを求めるもの
   - Vol 10 の IXC 応答要求のうち初期化・VARY XCF・sysplex に関するもの
   - JES2 Messages のうち初期化／終了モジュール（HASPIR*、HASPTERM、HASPWARM）が出す応答要求・終了メッセージ、$P JES2 関連
   - Vol 7 / Vol 8 の操作コマンド（REPLY/START/STOP/CANCEL/FORCE/HALT）が拒否されるメッセージ
   - System Codes の待機状態コードのうち IPL/NIP/LOADxx/IODF/SYSRES/マスターカタログに関するもの
2. その中から、オペレーターの操作で起こり、操作で回復できるものを選んでシミュレータに実装し、1件ずつテストケース化（[error-catalog.md](error-catalog.md)、86 件）
3. テストランナーは「エンジンが出しうる全メッセージ ID・待機状態コードがテストで1回以上出たか」「すべてに解説と出典があるか」も検査
