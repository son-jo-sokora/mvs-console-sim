# MVS IPL シミュレータ

ブラウザだけで動く、z/OS（MVS）の IPL とシャットダウンを練習するためのシミュレータです。
HMC からシステムを LOAD し、オペレーターコンソールで初期化中の質問に応答して JES2・VTAM・TCP/IP・TSO を立ち上げ、決められた順番で止めるところまでを体験できます。

### ▶ 今すぐ試す: https://son-jo-sokora.github.io/mvs-ipl-sim/

上のリンクを開くだけで使えます。ダウンロードやインストールは要りません。

- **インストール不要**です。`index.html` をブラウザで開けば動きます。
- メインフレームの実機やアカウントは要りません。
- 「障害シナリオ」を選ぶと、ボリューム名の重複、マスターカタログの指定誤り、JES2 のチェックポイントのロック残り、取り消しできないジョブなどを仕込めます。間違え方と回復の練習に使えます。
- コンソールのメッセージをクリックすると、意味と z/OS 3.2 マニュアルの出典ページが表示されます。
- [IPL・停止の手順例（16本）](https://son-jo-sokora.github.io/mvs-ipl-sim/procedures.html) から、同じ状況をシミュレータで試せます。
- 付録の[演習シナリオ（17本）](https://son-jo-sokora.github.io/mvs-ipl-sim/scenarios.html)は、計画停止から再 IPL までを通しで行う練習問題です。答えを見ずに挑戦し、採点と解説で確認できます。
- **[JCL 練習端末（jcl-terminal）](https://son-jo-sokora.github.io/jcl-terminal/)と連携できます。** 別のタブの jcl-terminal で投入したジョブが、このシミュレータの JES2 で実行されます。データセットの奪い合い、ジョブからの問い合わせ、保留ジョブ、再起動をまたぐジョブなど、利用者とオペレーターが関わる場面を体験できます（[5. 連携モード](#5-jcl-terminal-との連携モード)）。

> [!IMPORTANT]
> これは本物の z/OS ではなく、学習用のシミュレーションです。メッセージの番号や文面は z/OS 3.2 のマニュアルと照合していますが、実機と異なる場合があります。灰色の斜体で表示される「（シミュレータ注記）」は、このシミュレータ独自の説明で、実際の z/OS には表示されません。マニュアルに記載が見つからなかった挙動の扱いは [docs/decisions.md](docs/decisions.md) にまとめています。業務や試験の正解として扱わず、実機の動作は IBM のマニュアルとサイトの運用手順書で確認してください。

IEA371I SYS1.IPLPARM ON DEVICE 0A82 SELECTED FOR IPL PARAMETERS

## 1. 自分の PC で試す

必要なのは、新しめのブラウザ（Chrome、Edge、Firefox、Safari）だけです。

**とりあえず触ってみたいだけなら、[公開ページ](https://son-jo-sokora.github.io/mvs-ipl-sim/) を開けば十分です。** 自分の PC に置いて使いたい人や、改造したい人は、次の3つの方法から選んでください。

### 方法 A: ZIP をダウンロードして開く（いちばん簡単）

1. このページの上にある緑色の **「Code」** ボタンを押します。
2. **「Download ZIP」** を選びます。
3. ダウンロードした ZIP ファイルを展開（解凍）します。
   - Windows: ZIP を右クリック →「すべて展開」
   - Mac: ZIP をダブルクリック
4. 展開してできたフォルダの中の **`index.html` をダブルクリック**します。ブラウザで画面が開けば準備完了です。

> [!TIP]
> `index.html` は同じフォルダの `engine.js`・`msgref.js`・`procedures.js` を読み込みます。`index.html` だけを別の場所にコピーすると動きません。フォルダごと使ってください。

### 方法 B: git clone する

1. このページの緑色の **「Code」** ボタンを押し、表示された URL（`https://github.com/...`）をコピーします。
2. ターミナル（Windows は PowerShell、Mac は「ターミナル」）で次を実行します。`<コピーしたURL>` はコピーした URL に置き換えてください。

   ```bash
   git clone <コピーしたURL>
   ```

3. できたフォルダの中の `index.html` をブラウザで開きます。

### 方法 C: GitHub Pages で自分専用の URL を作る

1. このページ右上の **「Fork」** を押して、自分のアカウントにコピーします。
2. コピーしたリポジトリで **Settings → Pages** を開きます。
3. **「Build and deployment」** の Source で **「Deploy from a branch」** を選び、Branch で **`main`**、フォルダで **`/ (root)`** を選んで **Save** を押します。
4. 1〜2分待つと、同じ画面に `https://<あなたのユーザー名>.github.io/<リポジトリ名>/` という URL が表示されます。

### (任意) ローカルサーバーで開く

通常は不要です。ブラウザの設定で `file://` のページが制限されている場合だけ使ってください。Python が入っていれば、`index.html` のあるフォルダで次を実行します。

```bash
python -m http.server 8000
```

その後、ブラウザで `http://localhost:8000` を開きます。止めるときはターミナルで `Ctrl+C` を押します。

## 2. 最初の5分

1. 左の **HMC** 欄で、ロードアドレスが `0A80` になっていることを確認し、ロードパラメーターに `0A8200M1` と入力して **LOAD** を押します。
   - `0A82`＝IODF と SYS1.IPLPARM のある装置、`00`＝LOAD00、`M`＝メッセージを表示しプロンプトなし、`1`＝標準の核
2. 初期化のメッセージが流れ、`IEE389I MVS COMMAND PROCESSING AVAILABLE` の後に JES2 が `$HASP426 SPECIFY OPTIONS` と聞いてきます。中央下の入力欄に `R 01,WARM` と入れて Enter を押します（`01` は画面に表示された応答番号）。
3. `$HASP400 ENTER REQUESTS` が出たら `$S` と入力します。
4. `S VTAM`、`S TCPIP`、`S TSO` と順に入力します。`D A,L` で動いているタスクを確認できます。
5. 止めるときは、`P TSO` → `P TCPIP` → `Z NET` → `$P` → `$PJES2` → `Z EOD` の順に入力します。最後に `V XCF,SYSA,OFFLINE` を入力し、表示された応答番号で `R nn,SYSNAME=SYSA` と応答すると停止完了です。
6. 右の **「採点」** タブで、止める順番が正しかったかを確認できます。

次は、わざと間違えてみましょう。ロードパラメーターを `0A8201M1` にして LOAD すると、HMC に無効待機状態（待機状態コード 088）が表示されます。PSW の欄を押すと原因と対処が表示されます。

## 3. 画面とコマンド

| 場所 | 内容 |
|---|---|
| 左 | HMC（ロードアドレス・ロードパラメーター・LOAD・システムリセット・PSW 表示）と障害シナリオの選択 |
| 中央 | オペレーターコンソール。下に応答待ちのメッセージ（WTOR）の一覧と入力欄。上の「SYSLOG」タブで、コマンドを含むすべての記録を検索できる |
| 右 | 解説（メッセージの意味と出典）、手順書、使えるコマンド、採点 |

使えるコマンドは次のとおりです。↑↓キーで入力履歴を呼び出せます。

| コマンド | 意味 |
|---|---|
| `R nn,text` / `REPLY nn,text` | 応答番号 nn のメッセージに応答する。初期化（NIP）中に Enter だけ押すと空の応答 |
| `D T` / `D A,L` / `D R,L` | 時刻 / 動いているタスク / 応答待ちのメッセージ を表示 |
| `S JES2` / `S VTAM` / `S TCPIP` / `S TSO` | 開始。`S JES2,PARM='WARM,NOREQ'` のように開始オプションも指定できる |
| `P TSO` / `P TCPIP` | 停止 |
| `Z NET` / `Z NET,QUICK` | VTAM の停止 |
| `C jobname[,A=asid]` / `FORCE jobname[,ARM][,A=asid]` | ジョブの取り消し / 強制終了 |
| `$S` / `$P` / `$DA` / `$DU` / `$D JES2` | JES2 の処理開始 / 休止 / 実行中ジョブの表示 / 止まらない理由の表示 |
| `$P JES2` / `$P JES2,ABEND` / `$P JES2,TERM` | JES2 の停止（通常 / 強制 / 再 IPL まで再起動不可） |
| `Z EOD` | HALT EOD |
| `V XCF,SYSA,OFFLINE` | sysplex からの切り離し |
| `WAIT n` | （このシミュレータ独自）n 分経過させる。画面の「+1分」「+5分」ボタンと同じ |

## 4. 手順例・演習シナリオ・障害シナリオ

[procedures.html](https://son-jo-sokora.github.io/mvs-ipl-sim/procedures.html) に、16本の手順例があります。各手順の画面出力は、ページを開いたときにシミュレータで実際に操作を流して作っているので、シミュレータの表示と一致します。各手順の「シミュレータで試す」を押すと、同じ障害を仕込んだ状態でシミュレータが開きます。

| 種類 | 手順例 |
|---|---|
| 正常系 | 標準の IPL、パラメーターを指定した IPL（SYSP=・CLPA）、標準のシャットダウン |
| 停止時の対応 | バッチの終了を待つ、バッチを取り消す、取り消しできないジョブ（FORCE ,ARM）、同じ名前のジョブ（A=asid） |
| IPL 時の障害対応 | LOAD パラメーターの打ち間違い（088）、ボリューム名の重複（IEA213A）、共用 DASD の無応答（IEA120D）、マスターカタログの指定誤り（05F）、IEASYS00 がない、sysplex に停止済みシステムの記録（IXC405D）、JES2 のロック残り（$HASP479）、JES2 の初回起動（COLD）、時刻の確認（IEA888A） |

### 付録：演習シナリオ

[scenarios.html](https://son-jo-sokora.github.io/mvs-ipl-sim/scenarios.html) は、一晩・一日の業務を通しで行う練習問題です。手順例と違って正解の手順は最初に示さず、状況・連絡事項・作業指示書だけを渡します。途中で「（連絡）」が届いたり、作業の途中で新しいトラブルが起きたりします。

| No. | 演習 | 難易度 | 起きること |
|---|---|---|---|
| X1 | 月次の計画停止と、保守後の IPL | 中級 | 終わらないバッチ（業務担当の条件を守って取り消す）、保守中に増設されたディスクによるボリューム重複、パラメーターを指定した再 IPL |
| X2 | 夜間障害からの復旧 | 中級 | sysplex に停止済みシステムの記録（IXC405D）、JES2 のロック残り（$HASP479）。スプールを消さずに復旧 |
| X3 | 新人の IPL を引き継ぐ | 初級〜中級 | ロードパラメーターの打ち間違い（088）、マスターカタログの指定誤り（05F）とシステムプログラマーへの連絡 |
| X4 | 15 分以内の緊急停止 | 上級 | 同じ名前のジョブ、取り消しできないジョブ、TSO 利用者。時間内に正しい順番で止めて sysplex から外す |
| X5 | 新しいシステムの初回立ち上げ | 初級 | 時刻の確認（IEA888A）、JES2 の初回起動（COLD） |
| XL1 | 立ち上げ後に、利用者の確認ジョブで業務開始を判断する（連携） | 初級 | jcl-terminal で HELLO を流し、コンソールで正常終了を確かめる |
| XL2 | 「ジョブが終わらない」— データセット待ちを解消する（連携） | 中級 | 利用者の LINKRPT が IEF099I で待つ。原因の SALESUPD を見つけて取り消す |
| XL3 | 計画停止の前に、ジョブからの問い合わせに答える（連携） | 中級 | LINKASK の問い合わせに指示どおり NO と答えてから停止する |
| XL4 | 再起動をまたいで、保留ジョブを守る（連携） | 中級〜上級 | 保留中の HOLDJOB をウォームスタートで残し、再起動後に $DJ → $AJ |

| XS1 | 朝、利用者が TSO にログオンできない（SYSLOG 調査） | 初級 | 夜勤者の P TSO（IKT006I）のまま。SYSLOG で見つけて S TSO |
| XS2 | 夜間レポートが出ていない（SYSLOG 調査） | 中級 | NIGHTRPT が IEF099I で待ち。IEF863I のデータセットを使う SALESUPD を探して取り消す |
| XS3 | 夜間の IPL の後、ジョブが一切動かない（SYSLOG 調査） | 中級 | IPL 時の $HASP454 に N と答えられ JES2 が終了。WARM で起動し直して Y |
| XS4 | 投入されたジョブが始まらない（SYSLOG 調査） | 初級〜中級 | 停止準備の $P のまま（$HASP099）。$S で再開 |
| XS5 | 「夜間のジョブが異常終了した。オペレーターが止めたのか？」（SYSLOG 調査） | 中級 | PAYCALC は S806（CSV003I）。夜勤者が取り消したのは別のジョブ。再実行せず原因を伝える |

| C1 | 日勤の一日（複合） | 上級 | 朝の TSO 障害を SYSLOG で調査 → HELLO で業務開始確認 → 10 時にデータセット待ち → 15 時に問い合わせ応答 → 17 時に計画停止 |
| C2 | 障害の夜（複合） | 上級 | 23 時に SYSA がハング → リセットと再 IPL（IXC405D・$HASP479）→ 実行中だった利用者のジョブが $HASP406 で再実行 → 利用者の問い合わせに SYSLOG で回答 |
| C3 | 保守の日（複合） | 上級 | 保留ジョブを残して停止（バックアップは待つ）→ 保守でディスク増設 → パラメーター変更 IPL（IEA213A）→ 保留ジョブ解放 → 利用者の確認と問い合わせ |

XL と C で始まる演習は jcl-terminal と一緒に使います（[5. 連携モード](#5-jcl-terminal-との連携モード)）。

**複合演習（C1〜C3）** は、これまでの要素（SYSLOG の調査、jcl-terminal との連携、時刻で届く連絡、計画停止・IPL）を組み合わせた長めの演習です。決まった時刻に連絡が来るので、それまでは「+5分」ボタンや `WAIT n` で時間を進めます。事象ごとに「診断の報告」欄があり、採点も事象ごとに表示されます。前の事象での誤りが後の事象に響くこともあります（例: C1 で待っている側のジョブを取り消すと、原因のジョブが残って 15 時の問い合わせも 17 時の停止も進まない）。

**SYSLOG 調査演習（XS1〜XS5）** は、朝の交代でコンソールに着いたところから始まります。夜のあいだの出来事はコンソールには出ず、コンソールの上の **「SYSLOG」タブ**で調べます（検索できます。IMSI で非表示になったメッセージやコマンドも残っています）。原因の選択肢と根拠のメッセージ ID を「手順書」タブの **「診断の報告」** に記入してから対応します。採点は「原因」「根拠」「調べてから対応したか」「対応の結果」「余計な操作をしていないか」です。夜の出来事は、作り話ではなくシミュレータで実際に操作して作った記録です。

「シミュレータで挑戦する」を押すと、開始時の状態でシミュレータが開き、右の「手順書」タブに作業指示書が出ます（答えは出ません）。終わったら「採点」タブで、その演習専用の採点項目と経過時間を確認できます。ページの「解答と解説」には、模範解答（実際の画面つき）、判断のポイント、よくある誤りとその結果があります。

### 障害シナリオ

シミュレータ左の「障害シナリオ」は15種類です。チェックして「この設定で最初から」を押すと、その状態から始まります。「ランダム」は内容を伏せて1〜3個仕込みます（答えは「採点」タブ）。

## 5. jcl-terminal との連携モード

[JCL 練習端末（jcl-terminal）](https://github.com/son-jo-sokora/jcl-terminal)を別のタブで開いてつなぐと、オペレーター（このシミュレータ）と利用者（jcl-terminal）の両方の立場を1人で体験できます。

1. シミュレータの上にある **「連携モード」** を押します（`index.html?link` で開いても同じです）。
2. 表示される **「jcl-terminal を開く」** を押します。別のタブに jcl-terminal が開き、右上に「連携モード」と表示されます。
3. シミュレータで IPL し、JES2・VTAM・TSO を起動すると、jcl-terminal の USER01 が TSO にログオンします。
4. jcl-terminal で `SUB` したジョブは、シミュレータのコンソールに `$HASP100` で現れ、シミュレータの JES2 で実行されます。

| 起きること | シミュレータ（オペレーター） | jcl-terminal（利用者） |
|---|---|---|
| TSO が止まっている | — | ジョブを投入できない |
| `$S` の前、`$P` の後 | ジョブは入力キューで待つ | SDSF で入力待ちのまま |
| データセットを他のジョブが使用中（DISP=OLD など） | `IEF861I`・`IEF863I`・`IEF099I` で待つ。原因のジョブを取り消すと進む | 終わらない |
| ジョブの問い合わせ（練習用プログラム OPRASK） | コンソールに `OPR001A` が出て、`R nn,YES/NO` で応答 | 応答で結果（RC 0 / 4）が決まる |
| `TYPRUN=HOLD` | `$DJ` で確認、`$AJ` で解放、`$CJ` で取り消し | SDSF の H / A / C もシミュレータに送られる |
| 取り消し（`C jobname`） | `IEE301I`・`IEF450I` | ABEND S222 で終わる |
| 実行中にシステムリセット → ウォームスタート | `$HASP406` で再実行待ちに戻る | ジョブは入力待ちに戻り、再実行される |
| コールドスタート | スプールが初期化される | 投入したジョブと出力が消える |
| `P TSO` | `IKT010D` の利用者数に USER01 も入る | ログオフされ、投入できなくなる |

jcl-terminal には、連携演習用のサンプル `LINKRPT`（データセットを排他で使う）と `LINKASK`（オペレーターに問い合わせる）があります。

> [!NOTE]
> 2つのタブが同じサイト（同じオリジン）にあるときだけつながります。公開ページ（`son-jo-sokora.github.io`）ならそのまま使えます。手元で使う場合は、2つのフォルダを同じ親フォルダに置き、その親フォルダでローカルサーバーを起動して（`python -m http.server 8000`）、`http://localhost:8000/mvs-ipl-sim/` を開いてください。ファイルをダブルクリックで開いた場合はつながりません。

## 6. できること・できないこと

**IPL**
HMC からの LOAD（ロードアドレス・ロードパラメーターの検査）、LOADxx・IODF の選択、IMSI によるメッセージ表示とプロンプトの切り替え、マスターカタログ（IEA347A）、システムパラメーター（IEA101A、SYSP=、CONT、OPI=NO）、装置の問題（IEA311I・IEA120D・IEA213A・IEA214A）、時刻の確認（IEA888A）、sysplex への参加（IXC404I・IXC405D）、IPL 中の待機状態（00F・0B3・088・0B1・05F）

**JES2**
開始オプション（WARM・COLD・FORMAT・NOREQ ほか）、コールドスタートの確認、チェックポイントのロック（$HASP479・$HASP454）、初回起動、$S・$P・$P JES2 とその変形、止まらない理由の表示（$HASP607・$HASP608）

**停止**
TSO・TCP/IP・VTAM の停止、バッチジョブの終了待ち・取り消し・強制終了、HALT EOD、sysplex からの切り離し（IXC371D・待機状態 0A2）、停止手順の採点

**できないこと**
JES3、複数メンバーの MAS、相手システム（SYSB）側の操作、PARMLIB メンバーの中身の編集、実機との接続。ジョブの中身の実行は、連携モードで jcl-terminal が受け持ちます（連携していないときのバッチジョブは名前と実行時間だけの模擬です）。操作に関係するが未対応のエラー（IEA338A、IEA527A、IXC402D、$HASP490、$HASP620 など）は [docs/error-catalog.md](docs/error-catalog.md) の冒頭にまとめています。

**状態の保存**
状態はどこにも保存されません。ページを再読み込みすると最初からになります。

## 7. うまく動かないとき

**連携モードで「jcl-terminal 未接続」のまま**
- 2つのタブが同じサイトで開かれているか確認してください（公開ページ同士、または同じローカルサーバー上）。ファイルを直接開いた場合はつながりません。
- jcl-terminal の右上に「連携モード」と出ていなければ、URL の末尾に `?link` を付けて開き直してください。

**jcl-terminal で「TSO が動いていない」と言われて投入できない**
シミュレータで IPL して `S TSO` まで入力してください。TSO が動くと jcl-terminal が自動でログオンします。

**画面は出るが、LOAD を押しても何も起きない**
- `index.html` だけを別の場所にコピーしていないか確認してください。同じフォルダの `.js` ファイルが必要です。
- それでもだめなら、[1. の「ローカルサーバーで開く」](#任意-ローカルサーバーで開く) を試してください。

**応答したのに「IEE704I REPLY nn NOT OUTSTANDING」と言われる**
応答番号が違います。画面下の「応答待ち」欄か `D R,L` で、いま応答を待っている番号を確認してください。

**コマンドを入れても「初期化中（NIP）は応答か Enter のみ受け付けます」と出る**
IPL の途中です。`R 00,…` で応答するか、Enter だけを押してください。

**IEA370I などのメッセージが表示されない**
IMSI（ロードパラメーター7桁目）が `C`・`P`・`S`・`.` のときは、実機と同じく初期化中の情報メッセージが表示されません。`M` や `A` にすると表示されます。

**スマホで画面が縦長になる**
幅の狭い画面では、HMC・コンソール・解説が縦に並びます。PC か横向きで使うと見やすくなります。

## 8. 改造してみる

ビルドや npm は要りません。テキストエディタで書き換えて、ブラウザを再読み込み（F5）すると反映されます。

| ファイル | 内容 |
|---|---|
| `index.html` | シミュレータの画面 |
| `engine.js` | シミュレータ本体（ブラウザと Node.js の両方で動く） |
| `msgref.js` | メッセージ・待機状態コードの日本語解説と出典（書名・PDF のページ） |
| `procedures.html` / `procedures.js` | 手順例のページと、その手順データ |
| `scenarios.html` / `scenarios.js` | 付録の演習シナリオのページと、そのデータ（状況・連絡事項・作業指示書・途中で起きる出来事・採点項目・模範解答） |
| `link-mock.js` | 連携の相手として jcl-terminal と同じ受け答えをする模擬端末（テストと、演習ページの模範解答の表示に使う） |
| `tests/` | テスト。`cases.js` がエラーと連携のケース、`exercise-cases.js` が演習の誤答のケース、`runner.js` が実行部分、`run.html` がブラウザ用、`run-tests.js` が Node.js 用、`link-e2e.html` が本物の jcl-terminal との結合テスト |
| `tools/` | マニュアルからのエラー洗い出しと、`docs/` の一覧を作るスクリプト |
| `docs/` | エラー一覧、エラー候補の全件、設計判断のログ |

- **テストを流す**: GitHub Pages の [`tests/run.html`](https://son-jo-sokora.github.io/mvs-ipl-sim/tests/run.html)（またはローカルサーバー上の同じファイル）を開くと、エラーのテスト86件、連携のテスト18件（模擬端末が相手）、手順例16本、演習シナリオ17本の模範解答と誤答29件（採点が正しく減点するか）の、計166件を一度に実行して、成功・失敗を一覧にします。Node.js があれば `node tests/run-tests.js` でも実行できます。テストは、シミュレータが出しうる全メッセージ ID と待機状態コードが1回以上出ているか、すべてに解説と出典があるかも確かめます。
- **本物の jcl-terminal との結合テスト**: [`tests/link-e2e.html`](https://son-jo-sokora.github.io/mvs-ipl-sim/tests/link-e2e.html) を開いて「実行する」を押すと、シミュレータと jcl-terminal を2つの枠で開き、連携のテスト18件と、連携演習4本・複合演習3本の模範解答を実際にやり取りさせて確かめます（数分かかります。連携モードのタブを別に開いていると乱れるので閉じてから）。
- **手順例を追加する**: `procedures.js` の配列に、`steps`（`LOAD` / `CMD` / `WAIT` / `NOTE`）を書いた手順を追加します。応答番号は `R #$HASP426#,WARM` のように `#メッセージID#` と書くと、実行時の番号に置き換わります。
- **演習シナリオを追加する**: `scenarios.js` の配列に追加します。途中で起こす出来事は `triggers`（例: `{ after: 'reset', do: { scenario: 'DUPVOL', note: '…' } }` ＝システムリセットしたらボリューム重複を仕込み、連絡を表示）、採点は `checks` の関数で書きます。模範解答 `solution` で全項目 OK になることをテストが確かめます。
- **エラー一覧を作り直す**: テストケースを変えたら `node tools/make_errors_md.js` で `docs/error-catalog.md` を作り直します。`tools/extract_errors.py` は z/OS 3.2 のマニュアル PDF をテキスト化したファイルが手元にある場合だけ使えます（使い方はファイル冒頭に記載）。
